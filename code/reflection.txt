I learned when to use an accumulator to update a variable repeatedly. Initializing an accumulator before the loop 
lets the ETL pipeline turn many individual row-level values from cleaned_data into a single reliable aggregate during the transform step. For example, 
writing an accumulator for calculate_total_revenue in the transform module stored and 
added the revenue values from every row of the cleaned_data list of dictionaries when the loop in the function resets. I also strengthened 
my ability to trace data flow through a pipeline and recognize when a state needs to persist across iterations. I plan to practice this pattern 
on more complex aggregations like grouping revenue by a category, so I can get comfortable choosing the right 
accumulator structure for different outputs.
